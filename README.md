# AI-Agent

In addition to classical machine learning, I have hands-on experience with AI agent workflows, RAG-based LLM applications, and workflow-oriented automation. My recent work has focused less on standalone chat interfaces and more on building structured, semi-automated systems that support real operational use cases. In my skills summary, I already describe experience with AI agent workflows and RAG-based LLM application development and evaluation.

A representative example is an agentic intake and service workflow assistant I built using Dify for bioinformatics consulting operations. This system was designed to handle early-stage customer intake in a semi-automated way. When a new client inquiry arrived, the agent collected initial information, generated a preliminary solution outline, produced a workflow-style process diagram, packaged structured information into JSON, transmitted it to the backend, and created a case record for storage and later follow-up. This project was not just a “customer service bot”; it functioned as an intake orchestration agent that combined requirement capture, structured output generation, backend integration, and persistent case management.

This experience is especially relevant to agentic AI platform work because it involved several core agent-system elements:

### semi-autonomous workflow execution

### structured data capture and normalization

### backend handoff through machine-readable JSON

### record creation and persistent storage

### support for human follow-up after automated intake

Conceptually, this maps well to modern agentic system requirements such as tool invocation, workflow state management, memory/persistence, traceable handoff, and human-in-the-loop review.


Agentic AI and Workflow Automation Experience
1. Built an agentic intake assistant for bioinformatics consulting operations using Dify, enabling semi-automated client onboarding, initial requirement triage, and offline generation of preliminary solution plans.
2. Designed workflows that produced structured outputs, including draft analysis plans, process flowcharts, and standardized JSON intake records for backend ingestion and case creation.
3. Integrated the agent with backend storage to support record creation, information persistence, and traceable handoff from initial intake to human follow-up, improving response consistency and operational efficiency.
4. Designed the system for offline use, which is especially valuable for secure deployment involving sensitive biomedical or medical data.
5. Incorporated RAG-based retrieval and built-in SOP chaining, allowing the agent to assemble responses and preliminary plans in a more standardized, policy-aligned, and operationally consistent way.
